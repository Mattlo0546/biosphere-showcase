# Biosphere — working agreement for coding agents (Codex, Claude) and humans

Biosphere is a macOS SwiftUI app (`app/`) for IB revision: topical past-paper PDFs → iPad → marked by
**Hank** (the tutor, running on the student's own `claude` CLI) → results, spaced repetition, tracker.
One real user (an IB student) gets stable releases; Matt tests betas. Read `README.md` for the product.

**Orientation (read before coding):** `CLAUDE.md` explains what the app is, its engines and the UI/UX rules;
`docs/ARCHITECTURE.md` maps every file, on-disk format and flow. Update the map when you add or move files.

## Before you start any task

1. `git fetch && git checkout dev && git pull` — always start from the latest `dev`.
2. Create a branch: `feature/<short-name>` (or `fix/<short-name>`). **Never commit straight to `main` or
   `dev`.** Open a pull request into `dev` when done; keep PRs focused on one change.
3. Other agents may be working at the same time (often in `.claude/worktrees/*` or `codex/*` branches).
   Check `git branch -a` and open PRs (`gh pr list`). Prefer adding **new files** over rewriting shared
   ones; if you must edit a hot file (see below), keep the diff small and rebase on `dev` before the PR.

## Build, run, test

| Goal | Command |
|---|---|
| Live dev loop (rebuild + relaunch ~10–20 s after each save) | `app/scripts/dev.sh` (leave running) |
| Reload Hank's prompts/skills + question bank without rebuilding | **⌘R** in Biosphere Dev |
| Live UI previews (sub-second) | open `app/Package.swift` in Xcode → `Views/Previews.swift` → ⌥⌘↩ canvas |
| Compile | `cd app && swift build` |
| Tests | `cd app && swift test` (must pass before a PR) |
| Release build (rarely needed locally) | `app/scripts/build_app.sh` |

**Biosphere Dev** (`app.biosphere.dev`) is a separate app with its own data in `~/Biosphere-Dev`
(seeded once from `~/Biosphere`), reads `app/Resources` straight from the repo, and never self-updates.
Never test against the real `~/Biosphere` data unless asked.

## Releases (Matt only — agents don't publish unless explicitly asked)

- `main` = what she has. `dev` = integration. Versions are `app/VERSION` + git tags `vX.Y.Z`.
- Beta (Matt's Mac only): from `dev`, `app/scripts/release.sh X.Y.Z --beta`.
- Stable (her Mac): merge `dev` → `main` (fast-forward), then `app/scripts/release.sh X.Y.Z` on `main`.
- The app self-updates from GitHub Releases using a read-only token baked in at build time
  (`~/.biosphere-update-token`, never committed). Builds are signed with the self-signed
  "Biosphere Developer" identity so macOS permissions survive updates. Past-paper PDFs ship as a
  separate "paper pack" release (`app/scripts/release_papers.sh`), not inside the app.

## Product rules (from the user — don't regress these)

- Flow is **topic first, then time** ("How long have you got?" sheet), then the PDF is built and the timer loaded.
- Look: **80% white, 20% purple** (`Palette` in `Views/Theme.swift`). Light UI, purple accents.
- Tutor is **Hank**: friendly glasses bot (`Views/HankAvatar.swift`, animated moods), cool-biology-teacher
  voice (Crash Course energy, Amoeba Sisters clarity, Save My Exams layout). Chat answers are short and
  structured: bold one-line answer → ≤4 numbered steps → one 🧠 analogy → `> **Exam tip:**` → quick check.
  Persona: `app/Resources/template/CLAUDE.md`; chat format: `HankChat.chatPrompt`; skills: `app/Resources/skills/`.
- Maths is revised **by execution strategy**: she knows the formulas but can't tell which method a worded
  question wants. Drill one strategy (cut-down parts), then mix an area (spot the move; never print which
  strategy a question needs on a mixed paper), then exam-style whole questions.
- New questions come **newest exam session first** (2026 May → 2025 Nov → May → 2024 …); spaced repetition (SM-2) drives
  "My mistakes" / "Due for review".
- Never commit IB paper PDFs, raw extracted paper text (`pipeline/work/*/packets/`), tokens, or learner data.

## Where things live

- `app/Sources/Biosphere/Core/` — models, bank + selection (`Bank.swift`), spaced repetition (`Review.swift`),
  marking (`Marking.swift`), Claude CLI bridge (`ClaudeCLI.swift`, `HankChat.swift`), updater, paper pack.
- `app/Sources/Biosphere/Views/` — SwiftUI screens. Hot shared files (coordinate before big edits):
  `AppModel.swift`, `RootView.swift`, `ResultsView.swift`, `SessionsView.swift`, `TimeSheet.swift`, `HankPanel.swift`.
- `app/Resources/bank/<subject>/` — `questions.json`, `syllabus.json`, `index.tsv`, `pack.json` (generated by
  `pipeline/build_bank.py`; don't hand-edit). Papers in `papers/` are git-ignored.
- `pipeline/` — PDF segmentation (`segment.py`), labelling spec (`LABELING.md`, `LABELING_MATHS.md` + `label_maths.py`),
  Maths strategy catalogue (`maths_strategies.py`), validators, bank builder.

## Commits

Small, descriptive messages; one logical change per commit. Commit as the repo owner's configured git
identity and **do not add AI co-author trailers**.
