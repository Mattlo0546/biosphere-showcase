# Biosphere: architecture and file map

The whole app on one page: every directory and source file, what it owns, the data formats on disk,
and how the pieces talk to each other. Read `CLAUDE.md` first for the short version (what the app is,
the engines, the design rules); use this page to find the exact file before you open it.

Snapshot: v0.10.0 (October 2026), ~12k lines (Swift app ≈ 9.5k, Python pipeline ≈ 1.3k).
**Keep it current:** if you add, rename or delete a file, or change an on-disk format, update this page
in the same PR.

```

                         │   └─ 3-second poller: Downloads / iCloud "Done" for returned PDFs, requests/ for     │
                         │      Hank-built sessions                                                             │
                         └───────┬──────────────────────────────┬─────────────────────────────┬────────────────┘

          BusinessComposer       ▼                               ▼ ~/Biosphere)                ▼ or iCloud Drive
                     ~/Biosphere (workspace)  ◀────────── her own Claude Code CLI ─────▶   her iPad (writes on the PDF,
                     CLAUDE.md + .claude/skills    reads the same files (Hank)               AirDrops it back → Downloads)
                     bank/ sessions/ progress…
                                 ▲
                                 │ releases: app zip + paper pack (read-only token)
                          GitHub Releases (Mattlo0546/biosphere)
```

Key idea: **the app and Hank share a folder.** The app writes everything Hank needs (answer keys,
rendered page PNGs, progress summary) into `~/Biosphere`, runs the student's own `claude` CLI there
(so `CLAUDE.md` + skills apply), and gets structured JSON back. Biosphere never stores Claude credentials.

## 3. App entry: `app/Sources/Biosphere/BiosphereApp.swift` (97 lines)

- `BiosphereApp` (`@main`): no SwiftUI `WindowGroup`. Declares menu commands (⌘1 Show Biosphere,
  ⇧⌘S Screenshot to iPad, ⌘E Ask Hank, ⌘R Reload content) and a `MenuBarExtra` timer shown while a
  timer is active.
- `AppDelegate`: owns the single `AppModel` and builds the main `NSWindow` by hand (transparent
  full-size title bar, white background, min 1100×720, frame autosave `BiosphereMain`,
  `.preferredColorScheme(.light)`). Seeds dev data first (`AppModel.seedDevDataIfNeeded()`).
- `TimerMenu`: the menu-bar timer's menu (pause/resume, +5 min, stop).

### 6.1b Exam pack: `exam/business-hl.json` (read straight from Resources; ⌘R reloads it)

`{title, subtitle, subject, on_the_day:[…], blocks:[{id, minutes, title, goal, sections:[section ids], steps, check, hank}], sections:[{id, title, subtitle, icon, cards:[{title, subtitle, items:[ExamItem]}]}]}`.
`ExamItem.type` picks which fields are read (see `ExamPack.swift`). Blocks must add up to the time she has (tested in `ExamPackTests`).

### 6.3 Maths bank: `bank/maths-aa-sl/` (generated by `pipeline/build_bank.py "Maths AA SL"`)

Same files and `Question` shape as Biology, organised **by execution strategy** so she learns which method a
worded question wants. `syllabus.json` has `strategies: true`; themes `M1`–`M5` are the IB topics, topics
(`M5.2` "Using derivatives") are areas, and "subtopics" are strategies (`M5.2.7` "Optimisation in context")
with extra fields `ref` (IB syllabus section), `cues` (giveaway wording), `steps` (recipe), `formula`, `trap`.
Question ids start `AA-` so they never collide with Biology's in `progress.json`. Parts add `cue` (the words
in that question that signal its strategy) and `depends_on` (earlier lettered parts it needs).
**Drill items**: each long (Section B) question is also cut into one item per run of parts sharing a
strategy (id `<question>-<letters>`, e.g. `AA-2024M-P1-TZ1-Q8-d`), whose `regions` are the stem + the parts
it depends on + the part itself, with `parent` (the whole question) and `focus` (the drilled part labels).
`Bank.pool` (strategy banks): a drill (strategy or area) = drill items for those strategies + unsplit short
questions spending ≥ ⅓ of their marks on them; exam style (topic/everything) = whole questions by primary.
`Selector` never puts two members of one family (`Question.family`) in a paper. Crops stop before the
printed answer box; the app always adds working space. No multiple choice; 1.1 min per mark.
**Markscheme crops**: questions and parts carry optional `ms_regions` (same shape as `regions`) into
`papers/<paper_id>-markscheme.pdf`, which ships in the paper pack beside the paper; `QuestionResultCard`
shows each part's crop beside her answer (`Question.part(labelled:)` matches Hank's part labels loosely) and
falls back to the whole question's crop for parts without one. Her side of each row is her own handwriting:
for Maths the reader sees her lines numbered (L1, L2…, as for Business) and lists each part's line ids, the app
keeps each line's rectangle in `transcript.json` (`anchors`), and the card crops those lines from `completed.pdf`
(older transcripts show the typed text). Line ids and crop coordinates are stripped before Hank marks. `Bank.markschemeURL` is nil until a pack that
includes the markschemes is installed, so older packs just hide the pictures.
Bank stats: 106 official papers (2010 May–2026 May; scans and third-party copies without markschemes are
skipped), 1,016 whole questions (920 on the AA SL syllabus) + 878 drill items, 78 strategies. Labelled with Opus
via `label_maths.py` (~$0.50 per paper at API prices).

## 8. Flows

### 8.1 Session lifecycle (`SessionStatus`)

```
ready ──Send to iPad──▶ sent ──PDF returned──▶ completed ──▶ marking ──▶ marked
  │                                (Downloads/iCloud poll,           │
  └──────── drop PDF / Choose PDF… ─ drag-drop, file picker) ────────┴──▶ failed ──Mark again──▶ marking
```

### 8.2 Build a Biology paper (topic first, then time)

`SubtopicRow`/`ThemeCard`/review queue (or `MixBar` with `.custom(ids)` after pick-and-mix) sets `model.timeRequest` (+ `timeRequestMode`) → `TimeSheet` →
`AppModel.build` → `Bank.pool(for:format:)` → `Selector.pick(…mode…)` (mastery weights for mixed scopes)
→ `createSession` (requires `pack.isReady`) → `PDFComposer.compose` → `answer_key.json` + `session.json`
→ `openSession` (jumps to My sessions) → `timer.prepare`.
"Let Hank pick" instead calls `planWithHank` → `ClaudeCLI.ask(…, SessionPlan.schema)` → `validatedQuestions`
(rejects anything outside the chosen pool) → `createSession`.

### 8.3 Return and mark (Biology)

Poller (every 3 s, only while a session is `ready`/`sent`) finds a new PDF → `Marking.sessionId(in:)` →
`importCompleted` (copy to `completed.pdf`, stop timer, record time) → `mark` → `readAndMark`:
1. **Read** (cheap model): `Ink.pages` diffs `completed.pdf` against the PDF we sent → one sheet per answer
   placement that has ink (blank questions never reach a model) → `HandwritingReader.readBiology` (Haiku, batches
   of 8 in parallel, single turn, no tools, run outside the workspace) → `transcript.json`.
2. **Settle** (app): `decidedMCQ` marks clear multiple-choice letters; `needsLook` picks questions whose crop the
   marker should see (drawings, unclear writing, ambiguous choices).
3. **Mark** (her model): `Marking.markerContent` (skill + answer key + transcription + flagged crops) →
   `ClaudeCLI.ask(content:…, Marking.schema)` → `reconcile` (settled MCQs, ids, totals, stars from the reader).
Then `results.json` → `ProgressStore.record` (per-part subtopic attribution) → `writeSummary` → notification.
Measured on an 8-page paper: Opus marking went from 12 turns / $0.64 to 2 turns / $0.21 (+ ~$0.003 Haiku), same marks.

### 8.4 Business

One set: `BusinessSetRow` → `businessRequest` → `BusinessSheet` → `createBusinessSession` (optionally
`selecting(topic:)` with prerequisite parts) → `BusinessComposer.compose` → `business.json`.
Mixed: topic index → `businessPracticeRequest` → `BusinessTimeSheet` → `buildBusinessPractice` →
`BusinessPracticePlanner.plan` → `BusinessMixedPaper.compose`. Marking: `markBusiness` sends only
`answerPages` to the reader (`readBusiness`: every handwritten line gets an id L1… and an exact rectangle from the
ink) → marker gets marking pack + key + case **text** + lines by part (`BusinessMarking.markerContent`), returns
essay sentences with line ids → `placeSentences` (ids → anchors) → `BusinessMarking.validate` (labels, totals, choice groups, essay anchors) →
`business_results.json` → `BusinessAnnotations.write` → `marked.pdf` → `business_history.json`.
Business has no SM-2 schedule: `.due` is disabled; history = latest marked attempt per original part.

### 8.4b Economics

Exactly the Business flow (8.4) with `CaseSubject.economics`: `EconomicsView` → `businessRequest` / `businessPracticeRequest`
(scope carries `subject`) → `createBusinessSession` / `buildBusinessPractice` (bank from `caseBank(subject)`) →
`BusinessComposer` (Econs guide) → `markBusiness` (reader worded for Economics, `mark-economics` skill + Econs pack,
`economics_history.json`). Results use `BusinessResultsView`; Business-only reading links are hidden.

### 8.5 Chat with Hank

`⌘E` / Ask Hank → `HankChat.open` (fresh chat; never auto-sends) → `send` spawns `claude -p` with
`--append-system-prompt HankChat.chatPrompt`, `--resume <session>`, tools `Read Glob Grep Write Edit Skill
Bash(ls:*) WebFetch`, prefixed `[Biosphere context: AppModel.screenContext()]` → stream events update the
last bubble and Hank's mood → `chat.json`. Hank can create sessions by writing `requests/*.json`
(picked up by the poller → `handleRequest`).

### 8.6 Updates and paper pack

`Updater.check` at launch + every 6 h (stable only unless Beta updates) → "Update ready" in sidebar →
download `Biosphere.zip` → verify same signing identity → helper script swaps bundle and relaunches.
`PaperPack.ensure` at launch: copy from repo/`~/Biosphere` on dev Macs, else download the
`papers-biology-sl-<hash>` release asset and unzip into `bank/biology-sl/papers/`.

## 9. Engines at a glance (the rules worth remembering)

| Engine | Rule |
|---|---|
| Question selection (`Selector`) | Unseen before seen; newest exam session first (`year*2 + Nov`); questions longer than 60 % of the time go last; ~40 % of time on MCQ; MCQs printed first; multi-subtopic scopes interleave round-robin; mixed scopes weight red 3, orange 2, not started 1.5, green 0.3. |
| Study modes | Smart = due reviews ≤ 40 % of time, then new; New = never seen; Mistakes = lost ≥ 1 mark, worst first; Due = SM-2 due date passed. |
| SM-2 (`ReviewEngine`) | Grade from %: 100→5, ≥80→4, ≥60→3, ≥40→2, >0→1, 0→0. < 3 = lapse (due tomorrow, ease −0.2, min 1.3). Passes: 1st 1/3/4 days, 2nd 3/7, then interval × ease. Replayed from `progress.json`, no separate state. |
| Mastery (`ProgressStore.stats`) | Last 3 sessions on that subtopic: < 50 % red; ≥ 75 % with ≥ 8 marks, ≥ 2 sessions and latest ≥ 65 % green; else orange. |
| Timing | MCQ 1.5 min, written 1.25 min/mark (Settings-adjustable). |
| Reading | Ink = pixels ≥ 60/255 darker than the page we sent; pages that changed > 15 % (re-scans) or don't match in count/size fall back to plain crops. Reader transcribes verbatim, never sees markschemes. |
| Marking (Biology) | Her model marks the transcription in one turn; app settles clear MCQs; stars come from the reader (`uncertain: true` never changes marks); review list = lost marks ∪ unsure. |
| Marking (Business) | Only selected parts; exactly one per choice group; essays get band per strand, caps, labelled sentences, rewrite; result rejected if totals/labels don't match the key. |
| Inbox | Only watches Downloads while a paper is out (no early permission prompts); files already present when watching starts are ignored. |

### Running Biosphere Dev

From the checkout (or worktree) you want to try, in a terminal you leave open:

```
cd <checkout> && app/scripts/dev.sh
```

The first build takes a minute or two, then **Biosphere Dev** opens. It rebuilds and relaunches when a `.swift`
file is saved; Ctrl-C stops it. Prompt, skill and bank edits need no rebuild: press ⌘R in the app. Its data is

only in the checkout that built them until that subject's paper pack is published (`release_papers.sh`) and
